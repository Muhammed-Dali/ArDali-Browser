# Debugging ArDali Browser

This guide explains how to configure debug builds, capture runtime logs, analyze crashes with GDB, inspect Qt WebEngine internals, and diagnose subsystem issues safely.

---

## 1. Setting Up a Debug Build

To generate unoptimized binaries with full debugging symbols (`-g`) and clangd compile command databases:

```bash
cmake -S . -B build-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build build-debug -j$(nproc)
```

You can then run the debug binary directly or attach GDB:
```bash
gdb --args ./build-debug/ardali-browser
```

---

## 2. Terminal Logging & Diagnostic Environment Flags

Running ArDali Browser from a terminal reveals valuable real-time subsystem logs:

### 1. Chromium & WebEngine Diagnostic Logging
To route Chromium's internal logging directly to your terminal standard error:
```bash
QTWEBENGINE_CHROMIUM_FLAGS="--enable-logging=stderr --v=1" ./build/ardali-browser
```

### 2. Qt Framework Logging Categories
To filter or enable verbose Qt logging for WebEngine, networking, and widgets:
```bash
QT_LOGGING_RULES="qt.webengine*=true;qt.network*=true" ./build/ardali-browser
```

### 3. Chromium Remote Web Inspector
You can inspect browser tabs and internal web pages using a remote Chromium DevTools frontend:
```bash
QTWEBENGINE_REMOTE_DEBUGGING=9222 ./build/ardali-browser
```
Then open any Chromium-based browser (or another ArDali tab) and navigate to `http://127.0.0.1:9222` to inspect the DOM, console logs, network waterfalls, and JavaScript execution.

### 4. ArDali Internal Performance Diagnostics
ArDali includes a built-in diagnostics monitor that prints memory and subsystem metrics:
```bash
ARDALI_FEATURE_DIAGNOSTICS=1 ./build/ardali-browser
```

## 3. Investigating Crashes with GDB

If the browser crashes with a Segmentation Fault (`SIGSEGV`) or Abort (`SIGABRT`), run under GDB to capture the exact stack trace:

```bash
gdb -batch -ex "run" -ex "bt 30" ./build/ardali-browser
```

### Analyzing Core Dumps
If a core dump is generated by systemd:
```bash
# View recent crashes
coredumpctl list ardali-browser

# Open the most recent crash in GDB
coredumpctl debug ardali-browser
```

Inside GDB, inspect thread backtraces:
```gdb
(gdb) bt
(gdb) thread apply all bt
```

## 4. Subsystem-Specific Diagnostics

### Password Manager & Secret Service Keyring
ArDali binds vault wrap keys to the local machine via the Linux Secret Service API (`org.freedesktop.secrets` / `libsecret-1`).

- Check if Secret Service daemon is running:
  ```bash
  busctl --user status org.freedesktop.secrets
  ```
- Check stored ArDali keyring items:
  ```bash
  secret-tool search service ardali-browser
  ```
- Clear test keyring items (if diagnosing initial setup):
  ```bash
  secret-tool clear service ardali-browser
  ```

> [!CAUTION]
> **STRICT SECURITY WARNING:** Never add debug logging (`qDebug()`, `std::cout`, `printf`) that prints passwords, master keys, decrypted secrets, device keys, or fill tokens. All cryptographic keys and passwords must remain zero-wiped in RAM.

### Web Audio DSP & Equalizer
If web media audio is distorted or not processing:
1. Verify the audio effects panel at `ardali://audio-effects`.
2. Check terminal output for DALI Web Audio graph compilation errors.
3. Test with and without hardware audio acceleration:
   ```bash
   QTWEBENGINE_CHROMIUM_FLAGS="--disable-features=AudioServiceSandbox" ./build/ardali-browser
   ```

### ArDali Pulse (Music Recognition)
If song recognition cannot capture audio:
- Check available PulseAudio / PipeWire audio source monitors:
  ```bash
  pactl list sources short
  ```
  Look for `.monitor` sources (e.g. `alsa_output.pci-0000_00_1f.3.analog-stereo.monitor`).
- Launch with terminal output to inspect Shazam fingerprinting query status:
  ```bash
  ./build/ardali-browser ardali://pulse
  ```

### GeneralDownloadManager (Adaptive Parallel Downloads)
To observe connection scaling (1 → 2 → 4 → 8 chunks) and range chunking:
```bash
QT_LOGGING_RULES="ardali.downloads=true" ./build/ardali-browser ardali://downloads
```
Check if the remote HTTP server returns `Accept-Ranges: bytes` or returns HTTP 429 throttling headers.

### GPU & Video Hardware Acceleration
To verify VA-API video decoding pipelines:
```bash
# Verify VA-API driver on your machine
vainfo

# Launch browser with explicit driver if auto-detection fails
LIBVA_DRIVER_NAME=iHD ./build/ardali-browser
```
